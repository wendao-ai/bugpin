# Changelog 1.0.31

🚨 Hotfix：v1.0.30 部署后，PM 点「请求 AI 分析」前端报 502（lula 2026-06-05）。

## 🐛 Critical Fix

### `triggerAnalysis` endpoint 改 fire-and-forget

**问题**：v1.0.30 `POST /api/reports/:id/ai-analysis/request` **同步等待 SDK 完成（约 90 秒）才返回**。但 nginx 反代上游超时 30 秒，前端收到 502，PM 以为失败但**后端实际还在继续跑**。

**修复**：把 SDK 调用拆成两段：

```ts
async triggerAnalysis() {
  // 同步：pre-check + 写 analyzing 记录（<100ms）
  await reportsRepo.updateAiAnalysis(reportId, analyzingRecord);

  // 异步：SDK 调用 + 写最终结果（fire-and-forget）
  void runSdkAnalysisInBackground({...});

  return Result.ok(analyzingRecord);  // HTTP 立即返回
}
```

`runSdkAnalysisInBackground` 是独立函数：
- 完整 try/catch 兜底，任何异常都写 `failed` 状态（不会让 report 卡在 `analyzing`）
- 错误日志走 `logger.error`，主进程不会因为后台异常崩溃

### 前端轮询查 AI 分析状态

`ReportDetail.tsx` 的 useQuery 加 `refetchInterval`：

```ts
refetchInterval: (query) => {
  const aiStatus = query.state.data?.report?.aiAnalysis?.status;
  return aiStatus === 'analyzing' ? 3000 : false;  // analyzing 时每 3 秒拉一次
}
```

- 触发分析 → 立即收到 `analyzing` → 前端开始 3 秒轮询
- 90 秒后后端写 `awaiting_feedback` → 下次轮询拿到 → 渲染分析卡片
- 渲染后 status 不是 analyzing 了 → 自动停止轮询

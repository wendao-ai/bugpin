### #2 AI 分析模块（GLM）— 浅层 triage

**数据层：**
- migration 007：reports 表加 `ai_analysis TEXT NULL` 列
- initSchema 兜底 ALTER（防止 fresh / upgrade 路径不一致引发 502，参考 v1.0.27 教训）
- 索引：`idx_reports_ai_status` 按 `json_extract` 取 status

**设置项：**
- 新增 `aiEnabled` / `aiProvider` / `aiBaseUrl` / `aiApiKey` / `aiModel` 5 个 settings 字段
- admin 设置 → 系统 → AI 分析 子 tab，可配置开关 + GLM key + 模型

**服务层：**
- 新增 `ai-analysis.service.ts`，三个能力：
  - `triggerAnalysis()`：调 GLM `/chat/completions`（OpenAI 兼容），同步等待 → 解析 JSON → 写 ai_analysis
  - `applyFeedback()`：PM 对单个决策点选项后写 feedback；所有决策都答完 → 自动 confirmed
  - `confirm()`：PM 强制确认（即使还有未答问题）
- prompt 明确告诉 GLM「你看不到代码」「不给开发任务清单」「最多 3 个产品决策」
- 失败状态保留 error 信息和上一版的 feedback

**接口：**
- `POST /api/reports/:id/ai-analysis/request` — 触发
- `POST /api/reports/:id/ai-analysis/feedback` — 提交反馈
- `POST /api/reports/:id/ai-analysis/confirm` — 强制确认
- 全部需要 admin/editor 角色

**前端：**
- 新增 `AIAnalysisCard` 组件，渲染 5 个状态：idle / analyzing / awaiting_feedback / confirmed / failed
- 每个决策渲染成卡片：问题 + 推荐选项（带 ★）+ 备注输入
- 推荐选项点击即提交，蓝色高亮已选
- 「重新分析」按钮，版本号递增
- ReportDetail 侧栏底部挂载（仅 `settings.aiEnabled=true` + canEdit 用户可见）

## 🤖 GLM Provider 细节

- baseUrl 默认 `https://open.bigmodel.cn/api/paas/v4`
- 模型默认 `glm-4-plus`（推理质量优先，约 ¥0.05/分析）

- API key 走 password input，不在 UI echo

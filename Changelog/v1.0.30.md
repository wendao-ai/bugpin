# Changelog 1.0.30

AI 分析模块升级到「code-aware」深度分析（lula 2026-06-05）。

## ✨ Features

### AI 分析改用 Claude Agent SDK + GLM-4.6

之前 v1.0.29 用裸 GLM API 做浅 triage，PM 反馈「质量不够」。改用 Anthropic 官方 `@anthropic-ai/claude-agent-sdk` SDK，后端走 GLM 的 Anthropic 兼容 endpoint（api.z.ai/api/anthropic），让 GLM-4.6 主动用 Read/Grep/Glob 工具读 LIMS 源码做实锤分析。

**关键改动**：

- BugPin server 加 `@anthropic-ai/claude-agent-sdk` 依赖（SDK 自带 musl 版 Claude binary，零 Alpine 兼容性问题）
- `ai-analysis.service.ts` 重写：
  - 删 `callGlm` + `parseGlmJsonResponse` 裸 fetch 实现
  - 新增 `callClaudeAgentSdk` 用 SDK query() 跑多轮工具循环
  - `pathExists(LIMS_SOURCE_DIR)` 自动检测：
    - 有 LIMS 源码 → cwd=`/lims-source`，prompt 鼓励读代码
    - 无 LIMS 源码（dev 没 mount）→ cwd=`/tmp`，降级到无源码分析模式
  - 关键技术配置：`settingSources: []`（绕开 ~/.claude OAuth）+ 干净 env（只透 PATH/HOME/TMPDIR + ANTHROPIC_*）
- `AiAnalysisContent` schema 扩展：`rootCause.files[].lineHint`、`fixPlan.changes`，让 GLM 输出可定位的代码改动方向
- Settings 默认值：`aiBaseUrl='https://api.z.ai/api/anthropic'`、`aiModel='glm-4.6'`

### 报告创建自动触发分析

之前 PM 要手动点「请求 AI 分析」。现在 `createForProject` 末尾 async 触发 `triggerAnalysis`，PM 早上打开后台时所有新反馈已经分析完成。

```ts
void import('./ai-analysis.service.js').then(({ aiAnalysisService }) => {
  aiAnalysisService.triggerAnalysis({ reportId, triggeredBy: 'system:auto-on-create' });
});
```

`settings.aiEnabled=false` 时 service 内部返回 `AI_DISABLED`，主流程不受影响。

### Deploy workflow 加 LIMS 源码 mount

`/opt/lims-source:/lims-source:ro` —— BugPin 容器只读挂载服务器上的 LIMS 源码副本。

服务器侧一次性配置（lula 已做）：
- `/opt/lims-source/` git clone wendao-ai/mige-lims-jeecgboot
- cron 每 30 分钟 `git pull --ff-only`
